# EDA 测试用例生成 Skill 两层验证标准

版本：`2.0`

状态：`CONFIGURED`

## 1. 验证目标

顶层验收固定为两层：

```text
Layer 1：Skill 环境、工具与启动验证
Layer 2：端到端用户功能与输出验证
```

第一层证明 Skill 在目标 Agent 和主机上可被发现、可启动、依赖可用；第二层证明真实用户输入经过完整 Skill 流程后，输出符合版本化预期。只有两层均为 `PASS`，才能报告 Skill 验收通过。

Excel 规范检查和 TCL 规范检查继续保留，但它们是第二层的内部检查，不再单独充当顶层验证层。

## 2. Layer 1：Skill 环境、工具与启动验证

### 输入

- 待验收的 Skill 运行时目录。
- 目标 Agent 类型和 Skills 安装目录。
- Python、Tcl 及所需脚本的版本和位置。
- 可选的 EDA 工具、许可证、PDK 和设计数据可用性声明。

### 必检项

1. Skill 运行时结构完整，必需的运行时条目存在。
2. Skill 能被目标 Agent 扫描和识别，名称为 `eda-tester-skill`。
3. 显式触发词或与描述匹配的请求能启动 Skill，而不是回退成未加载 Skill 的普通回答。
4. Python 与 Tcl 满足最低版本，且基础环境自检通过。
5. Excel 生成、命令解析、设计配置和静态检查所需模块可以导入和执行。
6. 需要实机 EDA 执行时，明确记录工具、许可证、PDK、设计输入和 `PV_ROOT`/`PV_TOOL` 是否可用；缺失时返回 `TOOL_UNAVAILABLE`，不得记为功能通过。

Layer 1 不是业务功能测试，不比较测试计划或 TCL 的业务内容。Layer 1 未通过时，Layer 2 必须为 `SKIPPED`。

## 3. Layer 2：端到端用户功能与输出验证

### 输入

- 版本化端到端测试集。
- 每条测试的用户输入、附件或 fixture、上下文和前置条件。
- 该输入对应的预期输出和确定性比较规则。
- Layer 1 已通过的 Skill 运行环境。

测试集格式见 [端到端测试集规范](e2e-test-set.md)。

### 执行范围

每条测试必须从用户入口启动 Skill，完整经过需求解析、场景分解、Excel 生成、用户确认门禁、TCL 用例生成和交付校验。不得直接调用中间生成器来冒充端到端通过；中间脚本测试只能作为单元或组件测试。

### 输出比较

根据用例声明比较实际输出与预期输出，至少覆盖：

- 应交付的文件集合、目录结构、命名和非空性。
- Excel 工作表、字段、场景、步骤、预期和需求追溯。
- TCL 用例树、命令调用、初始化、检查点和收尾结构。
- 应出现的状态、诊断、缺口、确认请求或拒绝行为。
- 不应出现的秘密、用户本地路径、占位符和额外交付物。

Excel 规范检查和 TCL 规范检查作为第二层的内部检查执行。静态检查全部通过仍不等于端到端通过；测试集声明的完整预期输出也必须匹配。需要真实 EDA 结果的用例必须执行目标工具并比较运行输出，不能以静态检查替代。

## 4. 状态和门禁

| 状态 | 含义 |
|---|---|
| `PASS` | 本层全部必检项通过 |
| `FAIL` | 至少一个确定性检查或输出比较失败 |
| `TOOL_UNAVAILABLE` | 本层要求的外部工具、许可证或依赖不可用 |
| `SKIPPED` | 因上一层未通过而未执行 |

执行顺序：

1. 校验测试集和验证配置本身。
2. 执行 Layer 1。
3. Layer 1 为 `PASS` 后逐条执行 Layer 2；否则 Layer 2 为 `SKIPPED`。
4. 保存每条测试的实际输出、比较结果和诊断。
5. 只有 Layer 1 与全部 Layer 2 用例均为 `PASS` 时，整体结果为 `PASS`。

## 5. 测试集建设原则

- 先收录最小 Smoke 用户流程，再扩展正向、负向、边界、组合和工具差异场景。
- 每个已支持用户功能至少有一条端到端测试；关键拒绝和确认门禁必须有反例。
- 输入与预期输出必须去敏、可提交、可复现和带版本。
- 预期输出变化必须通过测试集版本变更审阅，不允许运行时临时放宽比较规则。
- Agent 可解释失败原因，但通过或失败必须由登记的比较规则确定。

## 6. 完成标准

- Skill 在所有声明支持的 Agent 环境中通过 Layer 1。
- 端到端测试集具有明确的输入及预期输出，并通过结构校验。
- 每条测试保存实际输出和确定性比较结果。
- Excel、TCL 及真实 EDA 结果按测试范围完成对应内部检查。
- Layer 1 失败会正确阻断 Layer 2。
- 不存在只运行静态检查就宣称端到端用户功能通过的路径。
