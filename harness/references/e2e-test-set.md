# 端到端用户功能测试集规范

版本：`1.0-draft`

状态：`CONFIGURED_DRAFT`

模型参与的真实 Codex Skill 用例还必须遵循 [Codex Skill Agent E2E 用例规范与范式](agent-e2e-pattern.md)。本文定义通用测试集数据契约；后者定义真实会话的执行、等待门禁、独立裁决和结果分类。

## 目的

测试集验证“用户给出输入后，Skill 的完整输出是否符合预期”。它不替代单元测试，也不把 Agent 的主观复核当成通过条件。

## 用例目录

```text
tests/e2e/<case_id>/
├── case.json
├── input/
├── expected_output/
└── actual_output/
```

`actual_output/` 可以由运行器放入临时目录；仓库只保留经确认需要归档的去敏结果。

## case.json 必需字段

- `schema_version`：测试集结构版本。
- `case_id`：稳定、唯一、可读的用例 ID。
- `feature_ids`：覆盖的 `function.json` 功能点。
- `input`：用户消息、附件引用、策略选择和确认响应。
- `fixtures`：输入文件、设计 profile 或 mock 工具的路径与哈希。
- `preconditions`：Agent、工具、许可证和环境前置。
- `expected_output`：预期文件集合、结构化内容、状态、诊断和禁止项。
- `comparison`：逐项比较方法，如精确文本、JSON 结构、工作簿规则、TCL 规则或规范化后 golden diff。
- `actual_output`：运行器写入的实际输出位置和采集范围。

## 比较规则

1. 每个预期项必须声明比较方式，不得由 Agent 自由判断“基本一致”。
2. 动态时间、临时目录和无业务意义的排序只能通过登记的规范化规则处理。
3. 忽略项必须逐字段声明并说明原因，禁止通配忽略整个输出文件。
4. `.xlsx` 先验证可打开、模板结构和规则，再比较规范化单元格内容及必要样式。
5. TCL 执行脚本规范检查，再比较目录树和关键语义结构；真实语法由目标 EDA 工具端到端执行验证。
6. 真实 EDA 用例必须记录退出状态、检查点、目标报告或数据库查询结果；环境不可用时返回 `TOOL_UNAVAILABLE`。

## 版本与审阅

- 测试集根目录维护版本和变更记录。
- 用户需求或输出标准变化时，先更新输入与预期输出并审阅，再修改实现。
- 每次执行记录 Skill 版本、测试集版本、环境摘要和结果。
- 测试输入、预期和实际输出均不得包含许可证、PDK、客户设计、运行日志秘密或用户本地绝对路径。
